Services

Workflow Reconstruction

Choose a task your team repeats, such as updating prices or passing orders to purchasing. We review how it is done, agree on a better process and build and test the tools it needs.

Improve one recurring piece of work

Workflow Reconstruction is our main service. We work with your staff on a task that takes too much time, needs repeat data entry or passes through several systems. The project covers the process and the tools needed to use it.

Good fit

  • People copy the same orders, prices, inventory or supplier data between systems
  • A spreadsheet or PDF is acting as the bridge between several tools
  • Legacy software has no API, but the repetitive work around it follows rules
  • A core-system change risks breaking workflows nobody has fully documented
  • One employee holds too much operational knowledge in memory

How the project works

  • Follow the work with the people doing it and review a few real examples
  • Identify where information is copied, checked twice or lost between systems
  • Agree on which steps a tool can handle and who needs to review the others
  • Write down the new process, including exceptions
  • Build the necessary automation, internal tool or connection between systems
  • Test it against the source records and compare it with the old process

What you get

  • The agreed process and instructions for using it
  • The working tools built for the task
  • Clear review points and instructions for exceptions
  • A way to recover when a tool changes business data
  • A recorded comparison: time taken, errors found, records handled or reconciliation results, as appropriate

Starting rule One workflow at a time. Fix the break before you buy more software.

Questions

How can we reconcile stock numbers across our website, POS and spreadsheets?
Start by agreeing which record is authoritative for each type of stock. We check product identifiers, units and update timing, then build a repeatable reconciliation process. Unmatched records and conflicting quantities go to staff for review before any write. See our price and inventory lookup case for related work; a shared lookup is not the same as automatic stock synchronization.
Can you reduce manual data entry when our old software has no API?
Sometimes. We first check file imports and exports, then whether the permitted desktop workflow can be automated reliably. A small trial must cover normal records, exceptions and read-back checks before wider use. Work that cannot be verified stays manual. See our legacy software automation case.
How do you approach moving from a legacy POS to Square without disrupting back-office work?
Map the current order, delivery, purchasing and commission processes before moving data. Check which rules Square supports and what needs another tool or a manual step. Test mappings and dry runs, agree the cutover and recovery plan, and reconcile records before switching. Our POS-to-Square case is still in progress: tooling has been built and dry-run, but it is not a completed migration.
Do we need to replace our current software?
Usually not. We check what your current software can do first. We discuss replacement only if it cannot support the agreed process.
How do you decide what to automate?
Work that follows known rules — moving, matching, formatting, looking up, entering data — is automated. Ambiguous cases, exceptions, approvals and final accountability stay with people.
Where do we start?
Choose a recurring task that takes too much time or causes frequent mistakes. Show us how it is done and a few examples of the files or records involved.
